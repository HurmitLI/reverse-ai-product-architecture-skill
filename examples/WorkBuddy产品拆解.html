01｜执行摘要

核心判断：WorkBuddy 的产品单位不是“一次回答”，而是一个可持续推进的 Task（任务）：它绑定对话、工作空间、项目规则、模型、工具调用、文件变更与最终产物。真正的差异化不是“模型会不会写”，而是能否把任务从输入一直推进到可查看、可修改、可分享的业务结果。 E01–E14
用户买的不是答案

完整交付

报告、Word、Excel、PPT、网页、代码修改等结果集中进入右侧“产物”区。

核心组织方式

任务 + 项目

任务负责一次执行；项目负责长期共享指令、资料、专家、技能、连接器和成员。

能力扩展方式

角色 + 动作 + 外部系统

专家决定“用什么专业视角”；技能决定“能执行什么动作”；连接器决定“能访问哪个系统”。

最大风险

真的会动手

它能读写文件、运行脚本、调用连接器和定时执行，因此权限、确认、审计和回滚比聊天质量更重要。

先用三句话看懂产品

1 输入

把目标和材料交给它

用户用自然语言描述目标，并通过工作空间、文件、截图、项目资料、个人记忆或连接器补充上下文。

2 执行

它规划、选模型、调工具

默认模式直接推进任务；Plan（计划）模式先整理思路；Ask（仅问答）模式只回答，不主动执行。

3 交付

用户核验真实产物

右侧区域同时展示工作空间文件、网页预览、文件变更和产物，用户可以继续修改、分享或放入项目资料库。

04｜核心功能地图：每个模块到底负责什么

Task｜任务

一次工作的执行容器

输入：目标、材料、模型、工作空间。
作用：承载对话、计划、工具调用与状态。
输出：回答、文件、网页、代码变更和产物。

Project｜项目

团队长期上下文

输入：指令、成员、资料、专家、技能、连接器。
作用：让项目内任务自动继承公共配置。
输出：共享任务、资产、动态和协作记录。

Expert｜专家

换一个专业角色做事

输入：领域人设、方法论、工具链。
作用：规定思考视角与交付方法。
输出：符合该专业角色的分析和产物。

Expert Team｜专家团

多个角色协同完成复杂任务

输入：复杂目标。
作用：团长拆解任务，多位专家并行执行并整合。
输出：跨角色的完整交付；积分通常更高。

Skill｜技能

让 AI 学会一个可复用动作

输入：参数、文件、任务上下文。
作用：运行封装脚本或工作流。
输出：查询结果、文件变化或外部动作。

Connector｜连接器

让任务访问外部系统

输入：用户授权和调用参数。
作用：通过 MCP / CLI 等桥接邮箱、文档、知识库、项目平台。
输出：外部数据或真实写入结果。

Workspace｜工作空间

本次任务读写文件的边界

输入：用户选定或自动创建的文件夹。
作用：限定文件读取与保存范围。
输出：任务文件、变更与最终产物。

Artifact｜产物

可交付、可验证的业务结果

包括：Word、Markdown、PDF、Excel、CSV、PPT、网页和代码。
关键：产物存在不等于内容正确，仍需用户验收。

Knowledge / RAG｜项目资料库

给任务提供项目事实

项目资产以检索增强方式进入任务上下文。简单说，就是先从项目资料里找相关内容，再交给模型使用。

Memory｜个人记忆

跨任务记住用户偏好

每晚从会话提取事实、偏好、关系和跟进事项；仅本人可见，可新增、修改、删除或关闭。

Automation｜自动化

按时间无人值守地重复执行

保存名称、提示词、模型、技能、工作目录和调度规则，到点以当前登录身份启动 Agent 任务。

Right Result Panel｜右侧结果区

边执行边验收

把概览、工作空间文件、浏览器预览、文件变更、产物和引用来源放在同一处，减少“AI 说完成但结果找不到”。

07｜最容易混淆的三个概念

Expert / Agent
专家 = 谁来做

它改变的是角色、判断框架和工作方法。

白话例子
让“战略咨询顾问”而不是通用助手来分析市场。
本身有没有权限
没有。只有配备技能或连接器并得到授权后，才会间接访问文件或外部服务。
适合
需要专业视角、方法论和固定交付标准的任务。
Skill
技能 = 会做什么动作

它把脚本和工作流封装成可重复调用的能力。

白话例子
Excel 文件处理、浏览器自动化、股票查询、发送邮件。
风险
可能读写本地文件、运行命令或把数据发送给第三方。
适合
输入和输出相对明确、可以反复执行的动作。
Connector / MCP
连接器 = 去哪里拿数据或执行

它把外部系统接入任务流程。

白话例子
腾讯文档、乐享知识库、QQ 邮箱、TAPD、Notion、GitHub、Supabase。
权限
每个连接器独立授权，不超过用户在第三方已有的权限。
适合
任务必须读取或改变外部业务系统时。
把三者连起来：“产品经理专家”决定用什么方法拆需求；“PRD 生成技能”负责执行固定写作流程；“腾讯文档连接器”负责读取旧需求并把新文档写回腾讯文档。三者不是同一层。

14｜As-Is 与 To-Be

As-Is｜已经确认的现状
  • 以任务为执行单位，以项目为团队上下文单位。
  • 默认、Plan、Ask 三种模式控制自主程度。
  • 专家、专家团、技能和连接器具有清楚的产品定义。
  • 项目资料通过 RAG 注入任务，并继承用户权限。
  • 右侧结果区同时展示文件、网页、变更、产物和引用。
  • 默认权限在敏感动作前确认；支持完全访问但风险高。
  • 个人记忆可管理；自动化可定时无人值守执行。
  • 个人订阅与企业坐席、专享、私有化商业模式并存。
As-Is｜仍然未知
  • Auto 模型路由的判断、回退和成本优化逻辑。
  • 内部真实 Agent 数量、消息协议、队列和调度服务。
  • RAG 的分块、召回、排序、冲突和无答案阈值。
  • 工具调用是否统一使用幂等键与失败补偿。
  • 分享链接的默认有效期、访问日志与企业 DLP 细节。
  • 模型 / 工具 / 任务 / 用户目标的线上评测指标。
  • Web、桌面、小程序和移动端的功能与状态一致性。
  • 自动化失败、积分不足或第三方中断后的补偿策略。

To-Be：最值得优先补强的设计

建议设计 P0

统一完成门

只有“工具成功 + 真实业务对象回读 + 产物存在 + 必要评测通过”后，任务才能显示完成。解决 Agent 自述完成与真实结果不一致。

建议设计 P0

外部动作预览与幂等

发送、创建、删除、发布前显示目标和参数；为重试绑定幂等键，避免重复发邮件、重复建任务或重复扣费。

建议设计 P0

自动化安全预算

每个自动任务设置积分上限、工具白名单、最大时长、数据外发范围、失败熔断和人工接管条件。

建议设计 P1

结果级证据与版本

报告句子、待办和结论能回跳到来源文件、段落、版本和时间；上游材料变化后提醒下游产物可能失效。

建议设计 P1

可解释模型路由

Auto 在执行前说明为什么选这个模型、预计倍率、是否支持图片 / 工具、失败如何回退，并把结果写入任务元数据。

建议设计 P1

权限与数据外发清单

在任务开始前生成一张清单：会读哪些本地目录、调用哪些连接器、把哪些数据发给哪个模型或第三方。

15｜术语翻译：看到英文时应该怎么理解

术语中文在 WorkBuddy 里是什么意思不要误解成
Agent智能体 / 能执行任务的 AI 角色会基于目标、上下文、模型和工具推进多步任务不是一定拥有系统权限，也不是持证专业人士
Expert专家用特定人设、方法论和工具链完成任务不是一个新的基础模型
Skill技能封装脚本和工作流，让 AI 执行某类动作不是只有一段提示词
Connector连接器连接邮箱、文档、知识库、项目系统等外部服务不是默认就拥有第三方全部权限
MCP模型上下文协议让 AI 用统一方式发现并调用外部工具和数据不是模型，也不是知识库本身
CLI命令行接口通过命令运行本地脚本或外部程序不是普通聊天文字，可能真正改变电脑状态
RAG检索增强生成先从项目资料中找相关片段，再让模型基于这些材料回答不是模型已经永久学会这些资料
Context上下文当前任务能参考的目标、对话、文件、项目、记忆、权限和工具结果不是所有历史数据都会无限加入
Memory长期记忆从历史会话提取、供未来任务参考的个人事实与偏好不是绝对正确的个人档案
Workspace工作空间任务主要读取和保存文件的目录不是整个电脑都可以随意访问
Artifact产物 / 交付物Word、Excel、PPT、网页、代码等可以实际使用的结果不是 Agent 说“已经完成”的一句话
Sandbox安全沙箱限制任务的文件、命令和网络操作，在高风险动作前要求确认不是绝对不会出错，也不能替代备份
OAuth第三方授权协议用户允许 WorkBuddy 在限定范围内代表自己访问外部服务不是把账号密码直接交给 WorkBuddy
API Key / Token接口密钥 / 访问令牌证明调用者身份并关联第三方权限或费用不是可以公开分享的普通配置
Credit积分 / 用量单位WorkBuddy 计算模型和 Agent 任务消耗的商业单位不等同于固定数量的模型 Token
RBAC基于角色的权限控制按查看、编辑、管理等角色决定人和 Agent 能访问什么不是“加入项目后什么都能看”
Auto自动模型选择由系统为任务选择模型；当前具体路由规则未公开不代表永远选质量最高或成本最低的模型

# 通用 AI 产品架构逆向分析

以可复核证据为边界，从用户体验逐步还原 AI 能力、Agent、模型、工具、上下文、知识、数据、安全和商业系统。适用于所有 AI 产品品类，不把 AIGC 视频的角色—场景—分镜流程强加给医疗、搜索、客服、编程或企业产品。

## 开始前

1. 读取用户指定的页面、截图、文件夹、对话、文档和已有分析。
2. 截图较多时先运行：

```bash
python3 scripts/inventory_screenshots.py <截图目录> --output <证据清单.csv>
```

3. 完整读取 [references/evidence-protocol.md](references/evidence-protocol.md)，建立证据编号、安全与隐私边界。
4. 读取 [references/product-type-routing.md](references/product-type-routing.md)，选择“AI 通用核心 + 品类扩展”，最多选三个扩展。
5. 根据交付深度按需读取：
   - 用户旅程、Agent 契约、System Prompt、HTML：
     [references/deliverable-specs.md](references/deliverable-specs.md)
   - 分层架构、上下文、数据实体、评测、安全和 To-Be：
     [references/architecture-schema.md](references/architecture-schema.md)
6. 已有产物只能作为索引；重要结论回查原始页面、可复核结果或官方资料。

## 证据等级

始终使用以下四类标签：

- 【已确认】：页面、官方资料或可复核结果直接支持。
- 【合理推断】：多条行为事实支持，但内部实现不可见。
- 【建议设计】：针对已观察问题提出的改进方案。
- 【未知】：当前证据不足。

若用户指定【页面事实】/【合理推断】/【尚未确认】，按用户标签映射，不混用两套口径。

## AI 产品通用核心工作流

### 1. 确定范围与风险等级

- 明确产品、版本、端、用户角色、任务、时间范围和交付深度。
- 判断是否涉及医疗、金融、法律、未成年人、个人数据或自动执行等高风险场景。
- 记录已查看与未查看页面、登录/权限限制、模糊截图和不同时间点。
- 浏览器默认只读；未经授权，不发送、支付、购买、发布、删除、提交、调用外部系统或触发高成本生成。

### 2. 建立产品认知骨架

先回答：

- 谁在什么情境下使用产品，原来如何解决问题？
- AI 在价值链中承担什么：生成、检索、判断、预测、推荐、规划、执行还是协作？
- AI 能力的输入、输出、可控性、失败代价和人类责任是什么？
- 首次价值时刻、持续使用循环和退出/转人工路径是什么？
- 产品宣传承诺与实际页面能力是否一致？

### 3. 还原用户旅程与任务流

- 从进入产品、授权、输入或任务入口开始，按时间追踪到结果、验证、保存、分享、执行或退出。
- 同时检查导航、按钮、表单、引用来源、解释、置信提示、确认门、空状态、加载、错误、权限和反馈。
- 每步记录用户目标、动作、页面反馈、决策、AI/系统处理、数据/状态变化、阻力和证据。
- 覆盖主流程、修改/追问/回退、失败/中断/恢复、额度/权限/安全拦截和人工接管；无样本时标【未知】。

### 4. 拆解 AI 能力契约

对每项核心 AI 能力记录：

- 要解决的用户问题与不负责的问题
- 输入模态、必填信息、上下文和用户控制
- 输出类型、结构、引用、置信与可验证性
- 自主程度：建议、草稿、需确认执行、自动执行
- 成功、失败、拒答、降级和转人工条件
- 延迟、成本、配额和结果质量要求

不要从结果像“AI”就推断具体模型、Agent 或 RAG。

### 5. 拆解 Agent 与工作流

- 识别实际出现的主控 Agent、专业 Agent、自动化步骤、业务服务和人工角色。
- 不预设 Agent 数量；名称不可见时使用“功能阶段/能力组件”，并标推断。
- 记录加入时机、触发者、上游、下游、重入、停止条件、确认门和能力边界。
- 为每个 Agent 建立六类输入、可观察判断、工具、五类输出、上下文读写、完成条件和异常重试。
- 页面没有 Agent 证据时，仍检查是否存在单 Agent、隐式编排或普通服务；结论保持【推断】或【未知】，不强行命名。
- 不把公开“思考完成/规划完成”还原为隐藏思维链。

### 6. 拆解模型、工具、上下文与知识

- 模型：已显示模型、模态、版本、参数、限制、成本、延迟、路由和回退。
- 工具：读取/写入对象、搜索、计算、生成、外部动作；计划不等于执行，结果/状态变化才确认。
- 上下文：当前输入、会话、用户长期信息、项目/任务状态、工具结果和权限。
- 记忆：临时、会话、长期偏好、用户私有知识；检查可见性、编辑、删除和过期。
- 知识：官方知识库、RAG 来源、引用、更新时间、权限和冲突处理。
- 数据：生产者—消费者、版本、引用、状态、审计和跨端一致性。

### 7. 拆解评测、信任与安全

- 结果验证：事实正确、来源可追溯、任务完成、业务规则、风格/格式、时效性。
- 用户反馈：满意/不满意、纠错、举报、采纳、修改和是否沉淀。
- 安全：输入/输出拦截、拒答、申诉、误判、越权工具调用和提示注入。
- 隐私：敏感数据、权限、保留、导出、删除、训练使用和跨租户隔离。
- 高风险产品：明确 AI 与人的责任边界，不把建议包装成诊断、决策或保证。
- 无页面证据时，不声称存在完整自动评测、安全链或合规实现。

### 8. 拆解功能域、状态与商业系统

- 按用户目标和业务对象聚类功能，不照抄菜单。
- 还原角色权限、对象生命周期、任务状态机、通知、历史、版本和异常恢复。
- 有证据时检查免费/付费边界、套餐、额度、用量、计费、退款、企业采购和运营后台。
- 区分 AI 结果成功、业务任务成功和用户目标达成。

### 9. 推导产品与系统架构

- 同时展示用户交互流、Agent/控制流、工具与外部服务流、上下文/数据流、结果/资产流和评测安全流。
- 拆分用户渠道、交互、应用领域、Agent 编排、工具服务、模型接入、上下文数据、知识记忆、评测治理和基础设施。
- 对数据库、队列、云、语言、模型供应商和向量库，只写所需能力、可能类别、推荐方案和不可确认原因。
- 输出 As-Is 与 To-Be；每个建议组件对应已观察问题或明确需求。

### 10. 按 AI 品类启用扩展

- 医疗/健康 AI：健康数据、证据来源、风险分层、人工复核、责任与合规。
- 搜索/问答/RAG：检索范围、引用、时效、权限、冲突与无答案处理。
- 助手/Copilot：上下文、建议与执行边界、确认门、撤销和多应用集成。
- 客服/运营 AI：意图、知识、工单、转人工、质检和 SLA。
- 编程/开发者 AI：仓库上下文、补丁、工具权限、测试、回滚和供应链安全。
- 企业 AI/SaaS：组织、RBAC、审计、连接器、数据隔离和企业计费。
- 推荐/决策 AI：候选、排序、解释、反馈、实验、公平和业务约束。
- Agent 平台/自动化：规划、工具、状态机、人审、幂等、补偿和可观测性。
- 多模态/AIGC：素材、提示词、生成模型、资产版本、一致性、版权和成本。

### 11. 生成 HTML 交付

- 使用 `assets/report-template.html` 作为结构与证据配色参考。
- 用旅程图、Agent 图、能力地图、上下文图、状态机、分层架构、ER 图、时序图和风险矩阵表达关系。
- 表格只用于契约、规则、字段、对比和证据追溯，不要整页卡片化。
- 每个关键节点标证据编号；全部说明写入 HTML 时，聊天只返回文件链接。
- 运行：

```bash
python3 scripts/validate_analysis.py <报告.html>
```

## 单 Agent 功能等价 System Prompt

只有用户指定目标 Agent 时执行：

- 先完成边界、输入、输出、工具、状态机、全局上下文和规则—证据追溯。
- 明确它不是官方原文，只复现可观察行为。
- 页面不可见的工具用 `<功能工具>` 占位，不伪造 API 名。
- 完成不能只依赖 Agent 自述；检查结果存在、上下文写入、验证、用户确认和下游交接。
- 测试正常、缺失输入、局部修改、工具失败、用户中断和状态冲突。

## 质量门

- 每个已确认结论可回到页面原文、交互、结果、状态、错误或官方资料。
- 没有把营销文案、常见 AI 架构或题目模板写成当前事实。
- Agent、模型、工具、RAG、记忆和动态路由未被默认存在。
- 聊天、任务、结果、数据和业务状态冲突被明确保留。
- AI 结果成功、业务任务完成和用户目标达成被分别判断。
- 医疗等高风险场景清楚标记人类责任与不能替代的专业判断。
- As-Is 与 To-Be 分开，建议有对应问题。
- 敏感信息、凭证和无授权私有数据未进入报告或仓库。

## GitHub 发布边界

- 默认只发布通用方法、模板、脚本和匿名化示例。
- 不提交用户截图、账号信息、Token、Cookie、原始私有对话、医疗隐私或未经授权的产品资产。
- 发布前检查 `git status`、`.gitignore`、目标仓库、可见性和 `git remote -v`。

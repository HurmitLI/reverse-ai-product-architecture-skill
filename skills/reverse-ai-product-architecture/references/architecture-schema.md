## 1. 十层架构

逐层检查，不适用项保留为未知或省略：

1. 用户与渠道：用户、专业人员、组织、角色、设备、入口和外部渠道
2. 交互与体验：对话、搜索、表单、工作台、解释、引用、确认、反馈、错误和无障碍
3. 产品应用与领域：围绕用户任务和核心业务对象组织的功能域
4. Agent 与流程编排：主控/专业 Agent、工作流、状态机、人审、重试、取消、补偿和完成门
5. 工具与外部服务：搜索、计算、业务 API、设备、支付、消息、文件和第三方系统
6. 模型接入与路由：文本、视觉、语音、多模态、Embedding、排序/预测模型和能力注册表
7. 上下文、记忆与数据：会话、用户、任务、工具结果、业务状态、事件、版本和审计
8. 知识与资产：RAG、官方知识、用户私有知识、模板、文件、媒体和生成结果
9. 评测、安全与人工治理：离线/在线评测、内容安全、权限、隐私、风控、人工复核和申诉
10. 基础设施与运营：认证、存储、队列、网关、可观测性、成本、实验、运营和灾备

页面没有多 Agent 证据时，第 4 层可表现为“单 Agent/工作流/未知编排”，不要虚构角色数量。

## 2. 上下文与记忆

语义对象模板：

| 对象 | 内容 | 重点检查 |
|---|---|---|
| IdentityContext | 用户、组织、角色、权限、套餐 | 租户与授权边界 |
| RequestContext | 当前问题、上传内容、参数、期望输出 | 输入完整与注入风险 |
| ConversationContext | 会话历史、摘要、引用 | 截断、版本与用户可见性 |
| TaskContext | 目标、计划、步骤、工具结果、状态 | 唯一事实源、取消和恢复 |
| DomainContext | 医疗记录、代码库、工单、订单等 | 领域完整性与责任 |
| MemoryContext | 长期偏好、事实、历史任务 | 写入条件、编辑、删除、过期 |
| KnowledgeContext | 公共/私有知识、来源、版本 | 权限、时效和引用忠实度 |
| ToolContext | 参数、权限、结果、错误 | 幂等、审计和越权 |
| ModelContext | 模型、提示词版本、参数、限制 | 路由、成本和可复现性 |
| EvaluationContext | 质量、反馈、风险、失败原因 | 完成门和是否跨用户沉淀 |
| BillingContext | 额度、冻结、用量、结算、退款 | 重试不重复扣费 |

## 3. Agent 与运行实体

实体名仅作分析模板：

- User, Organization, Session, Conversation
- Agent, AgentVersion, AgentRun
- Workflow, Task, Step, UserConfirmation
- Tool, ToolCall, PermissionGrant
- Model, ModelInvocation, PromptVersion
- ContextSnapshot, MemoryItem, KnowledgeSource, Retrieval
- BusinessObject, Asset, AssetVersion
- Evaluation, Feedback, SafetyEvent, Error
- UsageRecord, BillingRecord, AuditLog

关键关系：

- Task 由用户、事件或上游任务触发，由 Workflow/AgentRun 执行
- AgentRun 读取确定版本的上下文和权限，产生 ToolCall/ModelInvocation
- ToolCall 产生业务状态、资产、错误或外部副作用
- UserConfirmation 绑定具体动作、参数和版本，不只绑定自然语言
- Evaluation 验证 AI 输出、业务结果和风险后才允许完成/交接
- BillingRecord 绑定幂等调用；失败、取消和重试产生释放或补偿记录

## 4. 模型、工具与知识

### 模型能力目录

- modality、model_key、版本和生效时间
- 输入输出类型、上下文长度、结构化输出和工具能力
- 成本、延迟、并发、限额、失败率和可重试错误
- 安全限制、地区、数据保留和供应商边界
- 适用任务、评测结果、回退模型和废弃时间

页面只出现一个模型时，不得确认完整动态路由。

### 工具契约

- 输入 schema、必填参数、权限和副作用
- 调用前确认、幂等键、超时和取消
- 成功结果、状态写入、验证和审计
- 失败分类、重试、补偿和转人工

### 知识/RAG

- 来源、所有者、版本、更新时间和权限
- 分块、索引、检索、排序和引用（只有证据时确认）
- 无答案、低置信、多来源冲突和过期处理
- 用户私有知识与公共知识隔离

## 5. 评测、安全与人工治理

区分三类完成：

1. 模型/工具调用成功
2. 业务任务状态完成
3. 用户目标真实达成

评测至少按产品需要检查：事实、引用、完整性、格式、时效、业务规则、可执行性、用户满意和伤害风险。

安全治理：输入/输出审核、提示注入、越权工具、敏感数据、误拒、申诉、人工复核、红队、事故追踪和策略版本。

医疗等高风险场景把人类责任、转专业人员、紧急情况、来源证据和不可替代判断置于完成门之前。

## 6. 商业化与运营

有证据时检查：

- 免费/付费边界、订阅、席位、用量、额度、企业合同和 API 计费
- 预估、冻结、消耗、超限、失败释放、退款和对账
- 激活、采纳、任务成功、留存、成本、延迟和人工接管率
- 模型/Prompt/知识/安全策略的版本运营与灰度实验
- 客服、申诉、内容/知识运营和企业管理员控制

## 7. 风险与 To-Be

### P0

- AI 回复或 Agent 自述完成，但真实业务/资产/外部动作未完成
- 页面、任务、工具、数据和业务状态冲突
- 高风险建议无人工责任与升级路径
- 工具越权、敏感数据泄漏或跨租户访问

### P1

- 知识过期、引用错误、上下文污染或长期记忆错误
- 上游修改后下游结果未失效
- 重试不幂等导致重复动作或扣费
- 用户中断后后台继续
- 缺少回滚、审计和结果验证

### P2

- 模型能力变化后路由/提示词未更新
- 反馈只改当前回答，不进入可治理的评测闭环
- 只优化模型成功率，不验证用户目标和长期影响

To-Be 优先考虑：统一状态事实源、明确自主级别、权限/确认门、上下文版本、幂等与补偿、RAG 引用校验、完成门、全链路追踪、评测体系和人工治理。

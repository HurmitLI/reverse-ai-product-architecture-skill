## 1. 九层架构

逐层检查，但不要默认存在：

1. 用户与渠道：账号、权限、会员、额度、偏好、私有资产、历史项目、分享渠道
2. 交互与工作台：聊天、Agent 署名、画布、资产卡、表单、确认、任务、预览、剪辑、错误
3. 产品应用：项目、剧本、角色、场景、道具、分镜、视频、音频、资产、版本、发布
4. Agent 与编排：主控、专业 Agent、状态机、确认门、交接、中断、回退、重试、幂等、完成门
5. 工具与服务：上下文、解析、提示词、媒体生成、合成、预览、导出、安全、余额、计费、存储
6. 模型接入与路由：文本、图片、视频、音频/TTS、能力限制、成本、延迟、失败率、切换
7. 全局上下文与数据：用户、项目配置、创作对象、资产、任务、调用、确认、版本、错误、计费、反馈
8. 知识与公共资产：风格、专业知识、提示词模板、模型能力、安全、版权、计费、公共/私有资产
9. 基础设施与治理：认证、权限、数据库、对象存储、CDN、队列、模型网关、日志、追踪、评测、告警

## 2. 全局上下文

以下是语义对象模板，不是产品真实表名：

| 上下文 | 典型内容 | 关键消费者 | 重点检查 |
|---|---|---|---|
| UserContext | 用户、语言、会员、额度、个人资产 | UI、计费、权限 | 隐私和租户隔离 |
| ProjectConfig | 类型、比例、语言、风格、模型配置 | 全部下游 | 用户确认与版本 |
| ScriptContext | 原始输入、结构化剧本、版本 | 角色/场景/道具/分镜 | 修改失效范围 |
| CharacterContext | 角色、主图、多视图、Face ID、音色 | 分镜、视频、音频 | 稳定 ID 和一致性 |
| SceneContext | 场景描述、主图、多视图 | 道具、分镜、视频 | 完整性门禁 |
| PropContext | 道具描述、主图 | 分镜、视频 | 稳定引用 |
| StoryboardContext | 镜头、提示词、对象引用 | 视频/音频生成 | 引用完整和局部重算 |
| AssetContext | 媒体地址、版本、派生关系 | 预览、剪辑、下载 | 存在性和权限 |
| WorkflowState | 当前 Agent、任务、确认、错误 | 编排、UI | 唯一事实源 |
| BillingContext | 预估、冻结、消耗、退款 | 计费、任务 | 幂等 |
| EvaluationContext | 用户反馈、质量检查、失败原因 | 完成门、模型路由 | 是否跨项目沉淀 |

## 3. 知识与公共资产

区分：

- 项目数据：当前剧本、人物、场景、道具、分镜、生成结果、确认和错误
- 专业知识：剧本结构、镜头语言、影视知识
- 风格知识：style_id、视觉描述、负面约束、适用模型
- 模型能力知识：时长、分辨率、参考图、价格、延迟、失败率
- 平台规则：安全、版权、计费
- 用户私有资产：角色、音色、参考图、历史项目
- 平台公共资产：模板、示例、可授权素材

建议让规则在策略/工具层强制执行，Prompt 只负责解释和选择。

## 4. 模型路由

页面只出现一个模型时，不得推断完整动态路由。建议模型能力目录至少维护：

- modality
- model_key 与版本
- 支持输入类型
- 时长、分辨率、参考图和音频能力
- 内容安全限制
- 预计成本、延迟和失败率
- 可重试错误与回退模型
- 生效时间和废弃时间

路由顺序：用户显式选择 → 兼容性校验 → 安全与额度 → 模型调用 → 结果验证 → 写资产和账单。

## 5. 核心数据实体

实体名仅作分析模板：

- User, Project, Conversation
- Agent, AgentRun, Workflow, Task
- ToolCall, ModelInvocation, Error
- Script, Character, Scene, Prop, Storyboard
- Asset, AssetVersion
- UserConfirmation, BillingRecord, Feedback

关键关系：

- Project 聚合所有创作对象和工作流
- Task 由 Workflow 创建，由 AgentRun 执行
- AgentRun 产生 ToolCall；ToolCall 可产生 ModelInvocation、AssetVersion 或 Error
- Storyboard 引用 Character/Scene/Prop 的确定版本
- UserConfirmation 绑定被确认对象的版本，不只绑定阶段名称
- BillingRecord 绑定幂等调用；失败或取消产生释放/补偿记录

## 6. 风险与 To-Be

按优先级检查：

### P0

- 聊天、画布、任务、资产库和最终状态冲突
- Agent 口头完成但工具/资产未完成
- 资产成功但上下文写入失败

### P1

- 上游修改后下游未失效
- 自动重试重复扣费或重复创建资产
- 时长、风格、角色一致性、台词或音画未校验
- 用户中断后后台继续
- 用户私有资产权限泄漏

### P2

- 安全误判无解释与恢复
- 公共知识过期
- 模型能力变化后路由规则未更新

To-Be 组件必须对应至少一个已观察问题或明确产品需求。优先设计：

- 统一状态事实源
- 验证驱动的完成门
- 不可变 AssetVersion 与 DependencyGraph
- 局部重算和回滚
- 重试幂等与额度冻结
- 安全策略层
- 全链路 correlation_id
- 自动质量评测和用户可见缺失清单

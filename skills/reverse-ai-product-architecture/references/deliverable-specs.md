# 交付规范

## 目录

1. 用户旅程
2. Agent 清单与 I/O 契约
3. 单 Agent 功能等价 System Prompt

## 1. 用户旅程

### 证据表字段

| 阶段 | 用户目标 | 用户动作 | 页面反馈 | 用户决定 | 页面/资产变化 | 问题或阻力 | 证据 |
|---|---|---|---|---|---|---|---|

### 三条泳道

- 用户：想完成什么、做了什么、是否选择
- 产品界面：按钮、表单、卡片、提示、入口
- 系统结果：资产、状态、失败与下一步

### 必须表现的分支

- 满意 / 不满意
- 成功 / 失败
- 继续 / 中断
- 余额充足 / 不足（无样本时标未知）

每个判断用菱形；分支写条件；每个节点标 E/S 证据编号。

## 2. Agent 清单与 I/O 契约

### Agent 清单

| 顺序 | Agent | 加入证据 | 触发者 | 接替谁 | 交给谁 | 是否重入 |
|---|---|---|---|---|---|---|

不要预设 Agent 数量。没有独立音频、剪辑或质检 Agent 的证据时，明确“本场景未出现”。

### I/O 契约卡

固定结构：

1. 核心目标
2. 触发条件
3. 输入信息（六类来源）
4. 可观察判断
5. 调用工具
6. 输出信息（五类输出）
7. 全局上下文读写
8. 完成条件
9. 异常与重试
10. 尚未确认的问题

### 工具表

| 功能性工具名 | 使用者 | 输入 | 可见结果 | 执行证据 | 证据编号 |
|---|---|---|---|---|---|

若官方工具名不可见，在表头或说明中写“功能命名，非官方工具名”。

### 全局上下文表

| 字段或对象 | 可见值/状态 | 生产者 | 消费者 | 读/写 | 时机 | 证据 | 一致性问题 |
|---|---|---|---|---|---|---|---|

页面没有真实字段名时，使用语义名并标“推导字段”。

## 3. 单 Agent 功能等价 System Prompt

先完成以下分析，再写 Prompt：

- Agent 边界十问
- 输入契约
- 输出契约
- 工具契约
- 状态机与 Mermaid 状态图
- 事实、推断、建议规则

Prompt 固定结构：

1. Agent 名称
2. 角色
3. 核心目标
4. 任务边界
5. 输入契约
6. 全局上下文协议
7. 工作流程
8. 工具调用规范
9. 用户确认机制
10. 结果验证
11. 修改与回退
12. 异常处理
13. 状态机
14. 下游交接
15. 完成条件
16. 输出格式

用 `<功能工具>` 作为占位符。Prompt 必须说明它是功能等价版本，不是产品官方原文。

### 最小测试集

至少覆盖：

1. 正常输入完整
2. 缺少必要输入
3. 局部修改
4. 工具失败
5. 用户中断
6. 页面状态与上下文冲突

每个测试记录输入、初始状态、预期判断、预期工具、状态变化和禁止行为。

## 4. 完整产品架构

建议最终顺序：

1. 执行摘要
2. 证据来源与缺口
3. 核心功能域
4. 端到端五流表
5. 九层产品架构
6. Agent—工具—上下文关系
7. 全局上下文架构
8. 知识与公共资产架构
9. 模型接入与路由
10. 底层选型表
11. 数据实体表和 ER 图
12. 端到端时序图
13. 产品全景主图
14. As-Is
15. To-Be
16. 风险
17. 架构组件—证据追溯
18. 未知问题

主图线型：

- 实线：已确认
- 虚线：合理推断
- 点线或橙色：建议设计

箭头必须标调用、读取、写入、事件、确认、资产引用或状态更新。

## 5. HTML 可视化

### 信息层级

- 顶部：一句话架构结论和主流程
- 中部：用户旅程、Agent 流、分层架构、上下文和模型
- 下部：实体、时序、As-Is/To-Be、风险、追溯和未知

### 视觉要求

- 用泳道、节点链、分层地图、状态图、依赖图和风险矩阵表达关系。
- 避免所有内容都使用相同卡片。
- 大表格只放精确字段和追溯信息，并支持横向滚动。
- 标签颜色全页一致；颜色不能替代文字标签。
- 移动端把多列布局降为单列；宽图允许横向滚动。
- Mermaid 不能可靠渲染时，保留源码并提供静态降级图。

### 交付规则

- 用户要求“HTML 地址”时，把范围、缺口、证据、结论和停止点全部写入页面。
- 聊天只给可点击的绝对文件链接。
- 不在聊天重复报告全文。
